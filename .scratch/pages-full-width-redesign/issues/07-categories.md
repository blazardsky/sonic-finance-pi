## Comments

Implemented in `web/src/pages/Categories.tsx`, adapted from tickets 03–06's pattern to this page's shape: a short add-form and a management table, no per-row "load into the form to edit" flow (there's no equivalent of Expenses/Incomes' whole-entry edit — only a name can be changed, in place). Reused the shared `FormSidebar`/`Sidebar` unchanged. Root container is `mx-auto flex w-full max-w-(--content-max-width) flex-col gap-6 p-6`; a `flex flex-wrap gap-6` row holds the table (`flex-1 min-w-0`) on the left and `<FormSidebar title={t.addCategory}>` on the right, holding only the add-category form — always in "add" mode, no edit-mode title switch, since renaming is handled elsewhere (below). `error` (from add, rename, hide/unhide, or delete — any of which can 409) stays in the list column, same reasoning as ticket 05: it can be triggered by a row action while the sidebar might be closed.

Row actions: the three inline buttons (Rinomina/Nascondi-Mostra/Elimina) became a `DropdownMenu` (`RiMoreLine` trigger) — "Rinomina"/`RiEditLine` and "Elimina"/`RiDeleteBinLine` both `disabled={c.base}` (exactly mirroring the two `cmd/categories.go` checks: a Base category refuses a name/`applies_to` change and a delete, both with a 409 the frontend already had a message for), "Nascondi"/"Mostra" (`RiEyeOffLine`/`RiEyeLine`) always enabled — no merge/reorder/color items added, matching the ticket's explicit instruction. **Rename itself is unchanged** — still the existing inline behaviour (the dropdown's "Rinomina" click puts the name cell into edit mode, an `autoFocus` `Input` committed on blur/Enter or cancelled on Escape) rather than moving into the sidebar's form; the ticket asked to replace the row's *buttons* with a dropdown, not to redesign the rename interaction, and the existing one already works well for a single string field.

Bug found and fixed via live testing (not a `tsc`/build-time issue): triggering "Rinomina" from inside the `DropdownMenu` initially left the name cell's `autoFocus` input unable to actually hold focus — confirmed via a headless-browser check that `document.activeElement` landed on `<body>`, not the input, after the click. Radix's `DropdownMenu.Content` manages focus restoration on close (normally back to its own trigger button) on a timing separate from React's synchronous commit, and the menu's own close-teardown was winning the race against the freshly-mounted `autoFocus` input, even after `onCloseAutoFocus={(e) => e.preventDefault()}` was added to stop Radix's own restoration. The fix that actually worked: additionally deferring `setEditing(c.id)` by one tick (`setTimeout(() => setEditing(c.id), 0)`) inside the menu item's `onClick`, so the input mounts (and calls `.focus()` via `autoFocus`) after Radix's own close/teardown cycle has finished, not racing it. Confirmed via the same headless check that `document.activeElement` is now the input, and end-to-end that typing immediately after clicking "Rinomina" lands in the cell.

`applies_to` uses a `RadioGroup` (three `RadioGroupItem`s, each paired with a `FieldLabel`) rather than `Select` — with only three options it reads better fully visible at a glance in the sidebar than hidden behind an extra click, and this is the first ticket in this effort to actually use `RadioGroup` (installed in ticket 01, unused since).

Verified live: reused the dev password from tickets 03–06, `go run ./cmd` + `pnpm --dir web dev`, scripted headless-Chromium (Playwright). Confirmed at 1280px, 1920px and 390px: full-width layout, a real add-category submission (`POST /api/categories` 201) with the `RadioGroup` choice, the row dropdown's Rinomina (inline edit, confirmed committing via Enter — `PATCH` 200), Nascondi (`PATCH` 200, row shows "· nascosta" in muted text), and Elimina (confirm dialog, `DELETE` 204) all working end to end; a Base category's ("Investimenti") dropdown showing Rinomina/Elimina visibly and programmatically (`data-disabled` present) disabled while Nascondi stays enabled; the mobile FAB opening a genuinely full-width drawer with the `RadioGroup` rendering cleanly. `npm run build` (`tsc -b && vite build`) passes clean throughout.
