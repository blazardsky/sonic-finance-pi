## Comments

Implemented in `web/src/pages/RecurringExpenses.tsx`, the same treatment as tickets 03/04, reusing the shared `FormSidebar`/`Sidebar` unchanged — no fixes needed there, ticket 03 already covers the trigger z-index, `themed`, and `mobileWidth` issues at the shared-component level. Root container is `mx-auto flex w-full max-w-(--content-max-width) flex-col gap-6 p-6`; layout is a `flex flex-wrap gap-6` row with the list column (`flex-1 min-w-0`, keeping its existing `<h1>{t.recurring}</h1>` — a pre-existing duplicate of the header bar's own title, left as-is since removing it wasn't asked for) on the left and `<FormSidebar>` on the right, `title={editing === null ? t.addRecurring : t.editRecurring}`, wired to a `sidebarOpen` state so `selectRecurring` reopens a closed panel. The list column also keeps `error` (unlike Expenses/Incomes, this screen's errors come from row actions — end/replace/delete — just as often as from the form's own submit, and a row action can fire while the sidebar is closed, so it stays visible there rather than inside the form).

Row actions: this page already had three (Termina/Nuovo importo/Elimina, gated by `running(r)` for the first two) plus whole-row-click-to-edit — all four consolidated into one `DropdownMenu` per row (`RiMoreLine` trigger): "Modifica spesa ricorrente" (`RiEditLine`), "Termina"/`RiStopCircleLine` and "Nuovo importo"/`RiRefreshLine` (both only when `running(r)`), and destructive "Elimina"/`RiDeleteBinLine` — reusing the existing strings (`t.end`, `t.newAmount`, `t.delete`, `t.editRecurring`) as-is, no new copy needed. `end()`/`replace()` are unchanged; `remove`'s inline confirm+delete became `removeRecurring(r: Recurring)`, directly callable per row. Category and the conditionally-shown Holding picker (only for the Investments category, `disabled` + a hint when there are no Holdings yet — verified live) use the new `Select`; Payer and Payment method too, both via a shared `NONE` sentinel since — unlike Expenses' required Payer — both are optional here and default to "—" (`t.notSet`), which Radix `Select.Item` can't take as an empty-string value. Amount uses `Field`+`InputGroup`; Day of month, Holding, Store, Payer, Payment method, Note all use `Field`/`FieldLabel` (+`FieldDescription` for the day-of-month hint and the no-Holdings hint). The details disclosure (Store, Payer, Payment method, Note) is a shadcn `Accordion`, mirroring the `detailsOpen` state pattern from tickets 03/04.

Checked for the Accordion-skips-validation gotcha (tickets 03/04): none of this page's disclosure fields are `required` (Payer and Payment method both default to unset here, unlike Expenses/Incomes' required Payer), so no explicit pre-submit check was needed — confirmed nothing 400s when submitting with the disclosure never opened.

No date-like fields got the Date Picker recipe: this page has none — `day_of_month` is a plain 1–31 number, and Start/End month are `YYYY-MM` month values, not dates. Ticket 01's `DatePicker` is day-granularity (built on a day-level `Calendar`), so it doesn't fit a month-only value without truncating a date down to its month — out of scope here. The two native `type="month"` inputs stay as they were (the phone's own month picker, same reasoning `type="date"` was native before ticket 01 existed), just moved onto `Field`/`FieldLabel` and, per the width gotcha from ticket 04, stacked vertically rather than side by side — pre-emptively, given two side-by-side fields already overflowed the 16rem sidebar on ticket 04's Incomes page.

Verified live: reused the dev password from tickets 03/04, `go run ./cmd` + `pnpm --dir web dev`, scripted headless-Chromium (Playwright). Confirmed at 1280px, 1920px and 390px: full-width layout, a real add-recurring submission (Select category, day of month, open details, store name, submit — `POST /api/recurring` 201), the row dropdown's Modifica (loads the row), Termina (confirm dialog, `PATCH` 200, row now shows "terminata a MM/YYYY"), Nuovo importo (ends the old row, loads a new draft with store/day carried over, amount blanked, start month shifted — matching `replace()`'s intent exactly, not auto-submitted), and Elimina (confirm dialog, `DELETE` 204, row count drops) all working end to end; the sidebar toggle open/closed/reopen-on-edit via a real DOM click; the mobile FAB opening a genuinely full-width drawer with the stacked month inputs fitting cleanly; and the Holding picker showing disabled with its "Nessun investimento in elenco" hint when the Investments category is picked and no Holdings exist. `npm run build` (`tsc -b && vite build`) passes clean throughout.
